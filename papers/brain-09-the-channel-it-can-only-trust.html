Series II · Does the Brain Backpropagate?

The Channel It Can Only Trust

B08 settled that a frozen model can refine a reward reference but must borrow the standard that judges it. A borrowed standard arrives through a channel — a preference bit, an occasional correction, a fitness event — and B08 assumed that channel was a clean scalar oracle. It isn't, ever. So the sharp question is about the channel, not the reference: how thin, how sparse, how noisy can the imported signal be before refinement fails — and is the dangerous axis the channel's bandwidth or its honesty? The answer decides whether "just get more human feedback" is a fix or a trap.

Abstract

B08 reduced a frozen model to a loop that can tune a reward reference only when scored from outside. This paper takes the outside scoring apart. I reuse B08's world — a feature-bandit with value arms and salient distractors (high magnitude, zero value), an inner agent paid its felt reward w·φ, a gradient-free (1+λ) evolution search over the reference w — but replace B08's clean scalar oracle with a 1-bit pairwise-preference channel (the RLHF interface: which of two candidates is better), and vary it along four axes. Width: a single comparison bit recovers nearly all of the scalar oracle (true reward 116.6 vs scalar 134.5 vs oracle 123.7, random reference 60.8) — ~89% of the oracle-over-random span from one bit. Bandwidth is cheap. Sparsity: dropping most labels costs generations, not the fixed point — at 10% of generations labelled the loop reaches 84.1 in 25 rounds but 119.1 in 150; silence is a sample cost, recoverable. Noise is where the comfortable story breaks, and I report it straight: a noisy 1-bit accept does not average out with more rounds — it random-walks and gets worse (a coarse comparator, β=0.5, falls from 76.5 at 25 generations to 63.6 at 200, cosine going negative). Label noise is crossed only by aggregating bits within a comparison (majority vote of 1/3/9/25 bits → 76.5/89.0/113.8/124.2), i.e. by buying resolution per-decision, never by collecting more single-shot decisions. Bias is worst and qualitatively different: a comparator that over-credits salience is tolerated below the true value gap (bias 0–0.5 → ~116) and then flips the loop below random once it exceeds it (bias 1.0 → 44.8, below the 60.8 random baseline), and no amount of data corrects it (200 generations at bias 1.0 → 34.5, no better). The synthesis is one sentence: the scarce, load-bearing property of a borrowed channel is unbiasedness, not width — a thin, sparse, noisy-but-honest channel (78.9) beats a dense, high-resolution, biased one (45.6, below random). Evolution's channel to the brain is about one bit, maximally sparse (one verdict per lifetime), and yet suffices because survival is an unbiased proxy for the objective; RLHF's channel is fat but carries systematic human bias — length, sycophancy — which is exactly what the loop inherits and what "reward hacking" then names. B06's seam, refined: the frozen model does not need a rich imported signal; it needs an honest one, and it cannot audit the honesty from inside.

B08 ended on a specific promissory note, and this paper is the payment: how sparse and coarse can the imported signal be — a single bit of preference, an occasional correction — before reference-refinement fails? The instinct in the field is that the answer is "not very" — that alignment is bottlenecked on quantity of feedback, that more labels are always better. The measurement below says the instinct has the axis wrong. Bandwidth is cheap and sparsity is survivable; what the loop cannot survive is a channel that is confidently pointed slightly wrong, and it cannot tell from inside whether the channel it is handed is that kind.

The question, narrowed to the channel

Series II has walked one seam down three levels. A frozen model is all outer loop (B06); it cannot mint its own fitness signal (B07); it cannot originate its own reward reference, only refine a borrowed one (B08). "Borrow" is a verb that hides a mechanism. The reference is borrowed through something: for the brain, differential reproduction; for a reward model, a stream of human preference labels; for an agent in a session, whatever thin trickle of correction a user supplies. B08 modelled that channel as a clean scalar reward oracle and found the loop recovers near-oracle behaviour from it. But a real imported signal is never a clean scalar. It is a comparison (this answer over that one), it is sparse (most rollouts get no label), it is noisy (annotators disagree, err, tire), and it is biased (annotators systematically prefer longer, more confident, more agreeable answers whether or not they are better). The honest question B08 left open is which of those four degradations the refinement loop can absorb and which it cannot.

The reason this is not a detail is that the four degradations are usually lumped together as "imperfect feedback," and the standard remedy — collect more of it — is applied to all four indiscriminately. If they are not the same kind of defect, the remedy is right for some and actively wrong for others. The experiment below separates them so the difference is visible rather than averaged into a single "feedback quality" knob.

A world where the reference arrives through a channel

The world is B08's, unchanged, so the two papers are directly comparable. A K-armed feature world (K=10, features in R8): each arm k has a template μk; the true value of an arm is vk = a·μk for a hidden reference direction a (feature 0 — which features are actually worth wanting). Four value arms carry real value on the reference axis; four salient distractors carry near-zero value but large off-axis magnitude (norm ≈ 4), so the highest-feeling arm is always a valueless one; two neutral arms. An inner ε-greedy bandit is paid its own felt reward w·φ and is scored by the true reward it collects. A gradient-free (1+λ) evolution search tunes the reference w on the unit sphere. All of that is B08.

The one change is the scoring channel. B08 handed the outer loop a scalar (the true reward of a candidate reference). B09 hands it a single preference bit: to accept a mutant w' over the incumbent w, the loop asks a comparator "is w' better?" and gets one bit back. The comparator is a Bradley–Terry judge (Bradley & Terry 1952): it says yes with probability σ(β·Δ), where Δ is the difference in the quantity it cares about. Four knobs turn this from a clean oracle into a realistic channel:

  • Width — scalar reward vs the single accept/reject bit. (Is magnitude information needed, or is a ranking enough?)
  • Sparsity — a label is available only a fraction p of the time; otherwise the comparison is silent and the incumbent is kept.
  • Noise — the comparator's resolution β. Large β is a near-perfect judge; small β is a coin nudged by the truth. Optionally, m independent bits per comparison, aggregated by majority.
  • Bias — the comparator judges by true + c·salience: a systematic over-crediting of the vivid, high-magnitude distractors, exactly the shape of a human rater who prefers the longer or more confident answer. c is the bias magnitude.

Six seeds throughout; the reference is measured after tuning on 100 fresh episodes (a low-variance final score, separate from the noisy in-loop comparisons). Baselines: the oracle w=a scores 123.7 true reward/episode; a random reference scores 60.8. Those two numbers bracket everything below.

The first finding is the reassuring one, and it is real: a channel one bit wide recovers almost everything a full scalar channel does. Measured against the span between random (60.8) and oracle (123.7), the single preference bit recovers ~89% (116.6), against the scalar's essentially-full recovery. This is not surprising once stated: the outer loop is a selection process, and selection needs only an ordering of candidates, not the magnitudes of their rewards. A preference bit is exactly an ordering. This is the theoretical reason preference-based RLHF works at all (Christiano et al. 2017; Stiennon et al. 2020): you never need to elicit a scalar "goodness" from a human, only a comparison, and the comparison carries almost all of the usable signal. So on the bandwidth axis the news is good, and it will be the last good news that comes for free.

Now make the one-bit channel sparse: each generation is labelled only with probability p, otherwise the loop keeps its incumbent and moves on blind.

Read the last row against the second. At 10% labelling in 25 generations the loop only reaches 84.1 — halfway up. But the same 10% channel, given 150 generations instead of 25, reaches 119.1: essentially the fully-labelled result. Sparsity did not move where the loop converges; it slowed how fast it got there. This is the signature of an unbiased-but-scarce signal: each label still points the right way, so more rounds accumulate more correct steps and the fixed point is preserved. It is the same shape B04 and B05 found for unbiased gradient estimators — correctness in expectation, a cost paid in samples. On this axis, too, "get more feedback" is the right remedy: a sparse honest channel is a slow honest channel, nothing worse.

Result 3 — noise does not average out by repetition

Here the comfortable pattern breaks, and I am reporting the break rather than smoothing it. Degrade the comparator's resolution β — a smaller β is a judge closer to a coin flip — and hold everything else clean:

The naive expectation — the one that treats noise like sparsity — is that a coarse comparator just needs more generations to average out. It does not. A near-coin comparator at 25 generations scores 76.5; at 200 generations it scores 63.6, barely above random and with its alignment gone negative. More rounds made it worse, because the outer loop here is an accept-if-preferred walk, and a near-random accept bit turns that walk into a diffusion on the sphere: every extra generation is another chance to be pushed the wrong way, and the drift accumulates instead of cancelling. Noise in a single accept decision is not averaged by repeating the decision — each repetition is a fresh commitment, not a fresh sample of the same estimate.

The fix is aggregation, and it is bought per-decision, not per-round

Noise is crossable — but only by resolving each comparison better, not by collecting more comparisons. Give the loop m independent bits per comparison and take the majority (a Condorcet vote), holding generations fixed at 25:

Majority-voting 25 coarse bits recovers the oracle (124.2). This is the operational content of "average out the noise": you must aggregate within the decision the loop acts on, which is a resolution cost paid per comparison — the same shape as Series I's independence budget (No.08), where effective signal is bought by stacking noisy checks on one judgement. Collecting more single-annotator comparisons of new items does not substitute; it is the diffusion of the last table row.

Result 4 — bias transfers 1:1 and no data corrects it

The last and worst axis. Give the comparator a systematic lean: it judges by true + c·salience, over-crediting the vivid distractors — the sandbox form of a rater who prefers the longer, more confident, more agreeable answer regardless of whether it is right.

6 seeds; random 60.8, oracle 123.7. Note the two c=1.0 rows: more generations does not repair a biased channel — it deepens the error.

Two things here, both sharp. First, bias has a threshold: while the bias magnitude stays below the true value gap between a value arm and a distractor, it is harmless — c=0.2 and even c=0.5 leave the loop at ~116, because the comparator still ranks genuine value above dressed-up emptiness, just by a smaller margin. A biased channel is not automatically a broken one; a little bias is absorbed. Second, once the bias exceeds that gap, the loop does not merely degrade — it inverts. At c=1.0 it scores 44.8, below the 60.8 you would get from a random reference, because the comparator now genuinely prefers the distractor and the diligent outer loop optimizes straight toward it. And the punchline is the last row: running the biased channel ten times longer (200 generations) does not recover it — it reaches 34.5, if anything worse. Bias is not sample noise. It is a wrong fixed point, and more data converges harder onto the wrong point. This is B08's Result-1 reversal (and No.05's before it) reappearing at the level of the channel: an outer loop pointed at a systematically-wrong standard climbs, with all its competence, to exactly the wrong place.

Threats to validity — read before generalising

(1) The comparator is a hand-built Bradley–Terry judge, not a learned reward model. A learned reward model would add its own on-/off-distribution generalisation failure (the Gao–Schulman–Hilton 2023 overoptimization curve), which this sandbox does not model — but that failure is an additional way the channel goes wrong, so it strengthens the direction here, not weakens it. (2) The bias is a clean salience term. Real annotator bias is messier and only partly aligned with any single feature; the threshold finding is the honest hedge — below the value gap it is tolerated, and how large real bias is relative to real value gaps is the empirical question this predicts matters. (3) cos(w*,a) is a weak metric (argmax-over-arms, not an inner product); the true-reward column is the behavioural one and I lead with it. (4) The accept-if-preferred outer loop is a specific (1+λ) form. A population or rank-based ES would change the noise numbers (it aggregates implicitly) but not the two qualitative results — sparsity recoverable, bias not — which are properties of the signal, not the optimizer. (5) Six seeds, small world. Effect sizes are large (an order of magnitude between the honest and inverted regimes), so the ordering is safe; exact numbers are sandbox-specific. Script (numpy, fixed seeds) at scratchpad/thin_channel.py. The deep-policy / learned-reward-model / genuinely-multimodal-bias version is to-be-run-locally; the prediction is that width stays cheap, sparsity stays recoverable, and bias stays uncorrectable-by-scale.

Result 5, and the turn: a thin honest channel beats a fat biased one

Put the axes in direct competition. Build a channel that is bad on bandwidth — sparse (10% labelled), noisy (β=1), needing many rounds — but honest (bias 0, with modest per-comparison aggregation). Build another that is rich on bandwidth — dense (every generation labelled), sharp (β=8) — but biased past the threshold (c=1.0). Run both to 150 generations:

channelcos(w*, a)true reward / episode
thin + honest (sparse, noisy, unbiased, aggregated)+0.27678.9
fat + biased (dense, sharp, biased past threshold)+0.00845.6

6 seeds; random 60.8. The fat-biased channel lands below random; the thin-honest one lands above it.

The thin honest channel is not glorious — 78.9, well short of the oracle, because thinness genuinely costs. But it is positive-value and above chance, and it is improvable: pour in more rounds and it climbs, because it is pointed the right way. The fat biased channel is below random and gets no better with scale, because it is pointed the wrong way and all its bandwidth is spent going there. This is the whole paper in two rows: the scarce, load-bearing property of a borrowed channel is its unbiasedness, not its width. A frozen model does not, first of all, need a rich imported signal; it needs an honest one.

Now read the two real systems that borrow a reference. The brain's channel from evolution is almost the thinnest imaginable: the "label" is differential reproduction, effectively a bit or two, delivered at most once per lifetime — maximally coarse, maximally sparse. By Results 1–2 that is survivable, and it is survivable for the reason this paper isolates: the channel is unbiased with respect to the objective, because in the ancestral environment survival was the objective. Evolution paid in deep time (the sample cost of Result 2), not in honesty. Modern RLHF inverts the trade. Its channel is fat — millions of dense preference labels, a high-resolution learned reward model — but it carries systematic human bias, and the literature has now measured exactly the bias this sandbox uses: human preference data reliably favours longer answers (Singhal et al. 2023 — a purely length-based reward reproduces most of RLHF's apparent gains) and sycophantic ones (Sharma et al. 2023 — both humans and preference models prefer convincingly-written agreement over correctness a non-trivial fraction of the time). Those are the salience term c, in production. And the field's name for what a diligent optimizer does with a channel biased past threshold — Result 4's below-random inversion — is reward hacking (Amodei et al. 2016; Skalse et al. 2022): the policy climbs the reward model into the region where the model's bias and the truth diverge, and it does so harder with more optimization, exactly the two-c=1.0-rows finding. Scaling oversight is not, at root, about getting more feedback; it is about keeping the feedback's bias below the value gap, which is a property the loop cannot supply for itself.

What this establishes, and where the movement goes

B08 said the reference must be borrowed. B09 says the borrowing has a currency, and the currency is not bandwidth. Three of the four ways a channel degrades are the survivable kind — a single bit is nearly a scalar, sparsity costs only rounds, and unbiased noise is beatable by aggregating each decision — and all three are governed by the honest remedy "spend more samples." The fourth, systematic bias, is categorically different: below a threshold set by the true value gap it is tolerated, above it the loop inverts below random, and no amount of the standard remedy touches it, because more data on a wrongly-pointed channel is more confident wrongness. A frozen model, handed a thin trickle of correction within a session, can do real reference-refinement with it — but only to the extent the trickle is honest, and it has no internal instrument that distinguishes an honest thin channel from a biased one. That is the seam in its final, operational form: not "the model needs an external signal" (B06), not "it cannot mint the fitness" (B07), not "it cannot originate the reference" (B08), but "it cannot audit the honesty of the channel through which the reference arrives — it can only trust it." The next object is the audit itself: is there any internal check — consistency, cross-referencing multiple channels, adversarial probing — by which a loop could detect that its imported channel is biased before it optimizes into the trap, or is bias-detection strictly another thing that must come from outside? That is B10.

Coda

There is a hope that survives every result up to this one: that if the model just gets more of whatever signal it is given, alignment follows. B09 is the measurement against that hope. More is the right prayer for a channel that is merely thin, sparse, or noisy — those are honest poverties, and patience or aggregation pays them off. But more is precisely the wrong prayer for a channel that is biased, because more data on a channel that points slightly wrong is a more certain arrival at the wrong place; the diligence that rescues an honest channel is what damns a biased one. And the loop cannot tell which kind it has, from the inside, because the only instrument it could use to check the channel is the channel. Evolution did not give the brain a rich reward channel; it gave it a desperately thin one that happened to be honest, and paid the sample cost in eons. We give our models a rich one and spend our effort, rightly, trying to keep it honest — because we have learned that a confident, high-bandwidth, subtly-biased teacher is more dangerous than a mute one. A frozen model is the perfect student of whatever channel it is handed. That is its power and its exposure: it will faithfully become what it is told is good, and it cannot, from where it stands, check whether the telling is true.
